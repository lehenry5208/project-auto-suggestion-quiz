# Deploy ASQ to Render + Supabase

This guide walks through Supabase setup, local verification, and publishing to [Render](https://render.com).

---

## Part 1 — Supabase

### 1. Create a project

1. Sign in at [supabase.com](https://supabase.com) → **New project**
2. Choose a name (e.g. `asq-prod`), set a **database password**, and wait for provisioning (~1 min)

### 2. Copy credentials into `backend/.env`

| Variable | Where to find it |
|---|---|
| `SUPABASE_URL` | Project Settings → API → **Project URL** |
| `SUPABASE_SERVICE_KEY` | Project Settings → API → **anon / public** key |
| `DATABASE_URL` | Project Settings → Database → Connection string → **URI** → **Session pooler** tab (port `5432`) |

Replace `[password]` in the connection string with your database password.

Example `backend/.env`:

```env
DATABASE_URL=postgresql://postgres.[ref]:[password]@aws-0-[region].pooler.supabase.com:5432/postgres
SUPABASE_URL=https://[ref].supabase.co
SUPABASE_SERVICE_KEY=eyJ...
SECRET_KEY=<long-random-string>
OPENAI_API_KEY=sk-...
DEBUG=True
JUDGE0_URL=http://localhost:2358
```

> **Production:** set `DEBUG=False` on Render so the dev-login bypass is disabled.

### 3. Create database tables

1. Supabase dashboard → **SQL Editor** → **New query**
2. Paste the contents of [`setup_supabase.sql`](./setup_supabase.sql)
3. Click **Run**

### 4. Configure OTP auth (for teacher login)

1. **Authentication → Providers → Email** — enable Email provider, turn **Confirm email** off
2. **Authentication → URL Configuration**:
   - Local: `http://localhost:3000`
   - Production: `https://autosuggestions.onrender.com` (or your Render frontend URL)

## Part 2 — Run locally

```bash
./scripts/setup_local.sh
```

Then in two terminals:

```bash
# Terminal 1 — backend
cd backend && source venv/bin/activate && uvicorn main:app --reload

# Terminal 2 — frontend
cd frontend && npm start
```

- API: http://localhost:8000/docs
- App: http://localhost:3000
- Dev login (no email): enter `dev` on the login page when `DEBUG=True`

## Part 3 — Deploy to Render

### Option A — Blueprint (recommended)

1. Push this repo to GitHub
2. [Render Dashboard](https://dashboard.render.com) → **New** → **Blueprint**
3. Connect the repo — Render reads [`render.yaml`](./render.yaml) and creates:
   - **autosuggestions-backend** — Python/FastAPI API
   - **autosuggestions** — React static site
4. When prompted, set these **secret** environment variables on the backend service:

| Variable | Value |
|---|---|
| `DATABASE_URL` | Supabase Session pooler URI |
| `SUPABASE_URL` | Supabase project URL |
| `SUPABASE_SERVICE_KEY` | Supabase anon key |
| `OPENAI_API_KEY` | Your OpenAI key |

`SECRET_KEY` is auto-generated by the blueprint. `DEBUG` is set to `False`.

5. After deploy, update **Supabase → Authentication → URL Configuration → Site URL** to your frontend URL (e.g. `https://autosuggestions.onrender.com`)

### Option B — Manual services

**Backend (Web Service)**

- Root directory: `backend`
- Build: `pip install -r requirements.txt`
- Start: `uvicorn main:app --host 0.0.0.0 --port $PORT`
- Env vars: same as above + `DEBUG=False`, `FRONTEND_URL=https://<your-frontend>.onrender.com`

**Frontend (Static Site)**

- Root directory: `frontend`
- Build: `npm install && npm run build`
- Publish directory: `build`
- Env var: `REACT_APP_API_URL=https://<your-backend>.onrender.com`

### After deploy

1. Open the backend URL — you should see `{"status":"ok",...}`
2. Open the frontend URL and test login
3. On Render free tier, the backend may take 30–60 s to wake from sleep on first request

## Troubleshooting

| Problem | Fix |
|---|---|
| `tenant/user postgres.[ref] not found` | Wrong project ref or password in `DATABASE_URL`. Re-copy the Session pooler URI from Supabase. |
| `nodename nor servname provided` for `SUPABASE_URL` | Project deleted/paused, or typo in the URL. Confirm the project is active in the Supabase dashboard. |
| OTP emails not arriving | Check Supabase email settings; use `dev` login locally with `DEBUG=True` |
| Frontend can't reach API | Set `REACT_APP_API_URL` to the backend Render URL and redeploy the frontend |
| CORS errors | Set `FRONTEND_URL` on the backend to match your deployed frontend URL |
